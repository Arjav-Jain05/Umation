# 08. Web UI (plain HTML, CSS, vanilla JS; no build step)

Contents: 1 Principles · 2 `index.html` · 3 `job.html` · 4 Clip card · 5 Behaviour and states · 6 Editor (M5) · 7 Styling · 8 Accessibility and errors

## 1. Principles

- Served by FastAPI from `web/` at `/web/` (and `/` redirects to `/web/index.html`). No frameworks, no CDN, no external requests (works offline except Gemini/YouTube calls made by the backend).
- ES modules (`<script type="module">`). One `api.js` wraps `fetch` and `EventSource`.
- Dark theme, system font stack, mobile-friendly (the user may open it from a phone later via a tunnel).
- Every button shows a disabled/loading state while its request runs. Every error shows a red message box with the API `error.message`.

## 2. `index.html` (home)

Elements (use these exact ids; tests and scripts rely on them):
- `#sys-banner`: hidden unless `/api/system/check` has FAIL (red) or WARN (yellow); lists failing checks with their fix text. Loaded on page open.
- `#url-input`: text input, placeholder "Paste a YouTube video or finished livestream link".
- `#ack-fair-use`: checkbox, label: "I understand I am responsible for deciding whether I may reuse this video. The tool adds credits and risk flags but does not give legal advice." Required.
- `#options-toggle` opening `#options-panel` with: `#opt-min-tier` (select A/B/C, default C), `#opt-max-clip-s` (number, 20-90, default 60), `#opt-layout` (auto/gameplay/talking_head/facecam), `#opt-effects` (checkbox default on), `#opt-fast` (checkbox "Fast lane", default off), `#opt-quality` (checkbox "Max quality (1440p)", default off), `#opt-second-look` (checkbox, default off, disabled until M5).
- `#start-btn`: "Find viral clips". Disabled until the URL matches the allowed patterns (03 section 1) and `#ack-fair-use` is checked.
- `#jobs-list`: table of recent jobs: title, channel, status badge, stage, clips count, created time, link "Open". Auto-refresh every 5 s while any job is running.
Submit: `POST /api/jobs`; on 201 navigate to `job.html?id=<job_id>`; on 422 show the message under the input.

## 3. `job.html` (progress and review)

Query param `id`. Layout top to bottom:
1. **Header:** video title, channel, link to the original, status badge, `#cancel-btn` (visible while running), `#cleanup-btn` (visible when done).
2. **Progress panel `#progress`:** a list of stages with names, a thin progress bar each, an overall bar, and a text line `#progress-msg`. Subscribes to `/api/jobs/{id}/events`; on `progress` update bar + message; on `stage_done` tick the stage; on `warning` append to `#warnings`; on `error` show red box; on `done` fetch clips. If SSE drops, reconnect after 2 s and refetch `GET /api/jobs/{id}`.
3. **Summary `#summary`:** after the plan stage: "N clips found: A tier x, B tier y, C tier z", signal coverage ("Replay data: yes/no"), warnings.
4. **Filters `#filters`:** chips All / A / B / C / Approved / Rejected / Pending, and a sort select (score, time in video).
5. **Clip grid `#clips`:** clip cards (section 4). Cards appear as soon as each clip is `packaged` (via `clip_update`), and planned-but-not-built clips show as skeleton cards with their time range, score and status text.
6. **Bulk bar:** "Approve all A tier", "Open output folder" (`POST /api/system/open-folder`), "Download all approved (zip)" (client requests each zip sequentially).

## 4. Clip card (`.clip-card`, generated by `job.js`)

Contents:
- `<video controls preload="metadata" playsinline>` 9:16 box (aspect-ratio 9/16, max-width 260 px) with `src=/files/output/<folder>/clip.mp4` and `poster` = `cover_9x16.jpg`.
- Badges: tier (A green, B blue, C grey), score ("Est. viral potential 84"), risk (low green, medium amber, high red) with tooltip listing `risk_flags`, duration, "Part 1/3" if a Part.
- Signal mini-bars: Transcript, Replay, Audio (each 0-100; "n/a" for missing replay).
- Source time: "12:03 - 12:51" with a link `https://youtu.be/<id>?t=<s>` opening the original at that moment.
- Thumbnail preview (16:9) with a download link.
- Title select `.title-choice` (3 options) plus a text input `.title-override`; description `textarea.desc` (prefilled from `description_youtube`, editable); hashtags and tags display.
- Buttons: `Copy title`, `Copy description`, `Copy tags`, `Copy Instagram caption`, `Copy all` (the whole `metadata.txt`), `Download clip`, `Download thumbnail`, `Download zip`.
- Decision buttons: `Approve`, `Reject` (toggle; `PATCH decision`). Approved cards get a green border; rejected are dimmed and sorted last.
- `Why this clip?`: collapsible text from `notes` (reasons.overall, hook score, context fix).
- M4 adds `Log result`: small form (platform, url, views, likes) -> `POST .../results`.
- M5 adds `Edit` (opens editor, section 6) and `Re-render`.
Copy buttons use `navigator.clipboard.writeText` with a fallback textarea+`execCommand("copy")`, and show a 1.5 s "Copied" state.

## 5. Behaviour and states

| Situation | UI |
|---|---|
| Job queued | "Waiting for the worker" |
| Gemini quota reached | amber banner "Gemini daily quota reached. The job will continue when you press Resume tomorrow." + `#resume-btn` (calls `POST /api/jobs/{id}/resume` which sets status back to queued; add this endpoint) |
| Zero clips | message from 04 section 8 + button "Show weaker candidates" (re-plan with min tier C, no new Gemini calls) |
| A clip failed | card shows red text with reason and a `Retry` button (rerender) |
| Job failed | red box with `error`, link to the log file path |
| Battery power | yellow banner at top |
Never auto-play videos with sound; never autoplay multiple videos at once (pause others when one plays).

## 6. Editor (M5) (`editor.js`)

Opens as a modal for one clip:
- Video player with a timeline showing the clip's source range (+-10 s context); draggable **start** and **end** handles snapping to word boundaries; changing them calls `PATCH start/end` then `Re-render`.
- Transcript list under the player (words clickable to seek); click a word to toggle `emphasis` (stored in the clip's `edit_list.caption_emphasis`).
- Effects list from `edit_list.events`: each row has type, time, a delete button and (for hook_card/recap_line) a text field; deleting or editing calls `PATCH /api/clips/.../edit-list` (add endpoint: replaces events after validation) then `Re-render` (only stages direct+package).
- Overlay position drag for arrow/highlight/emoji on a still frame is optional (v2); not required in M5.

## 7. Styling (`css/style.css`)

CSS variables: `--bg:#0f1115; --panel:#171a21; --text:#e8eaf0; --muted:#98a0b3; --accent:#ffd400; --ok:#2ecc71; --warn:#f5a623; --bad:#ff5a5f`. Cards `border-radius:12px`, 16 px padding, grid `repeat(auto-fill,minmax(280px,1fr))`, gap 16 px. Buttons min height 40 px. Font size 15 px base. No animations except progress bars.

## 8. Accessibility and errors

Buttons have text labels; badges have `title` tooltips; focus outlines visible; colours not the only signal (badges contain text). All fetch failures show a message and never leave a spinner running. The UI never shows stack traces.
